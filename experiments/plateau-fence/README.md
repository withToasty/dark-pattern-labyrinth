# plateau-fence（実験・保留中）

PLATEAUの3D都市モデル（CityGML）を、道路沿いのフェンス・防護柵を検出する
画像認識の教師データ（bounding box / segmentation mask）として使えるか検証する実験。

**これは実験用コードで、本番（city-techno-vision等）には一切組み込んでいない。**

## 1. 目的

`city-techno-vision`の物体検出は現状YOLO系モデルを使っているが、
「フェンス」はCOCO・Open Images V7どちらの学習データにも存在しない
（bounding boxで囲む対象＝物ではなく、背景的に広がる構造物のため）。

PLATEAUの3D都市モデルには道路付属物（フェンス・柵・ガードレール等）の
位置情報が含まれている可能性があり、これを教師データ生成に転用できないか、
最小構成で検証した。

## 2. スコープ / やらないこと

- 本番実装への組み込みは行わない（あくまで検証）
- フルの学習・YOLO本番デプロイ・大量データセット生成・Webサービス化・GUI化は行わない
- 精度の最適化は行わない
- `Tk-work`フォルダには一切触れていない（読み込み・編集・書き込み・移動・削除・追加なし）。
  このリポジトリにそもそも`Tk-work`フォルダは存在しない
- `city-techno-vision`の依存関係・コードは変更していない。完全に独立したフォルダ

## 3. 仕様調査（ステップ1・完了）

PLATEAUの実データ付属コードリスト（`CityFurniture_class.xml` /
`CityFurniture_function.xml`、CityGML 3.0 / i-UR、`frn`＝City Furnitureモジュール）
を直接確認した。

### frn:class（大分類、4種類）

| コード | 内容 |
| --- | --- |
| 1000 | 交通施設 |
| 1010 | 通信施設 |
| 1020 | 保安施設 |
| 1030 | その他 |

### frn:function（詳細分類、フェンス関連は1種類のみ）

93個のfunctionコードのうち、フェンス・柵・壁に該当するのは**1つだけ**：

| コード | 内容 |
| --- | --- |
| **2000** | **柵・壁** |

道路標識(3000番台)や建造物(4000番台)などは細かく分かれているのに対し、
柵・壁は**サブカテゴリなしの単一コード**だった。つまりPLATEAUのデータだけからは
「ガードレールか」「転落防止柵か」「横断防止柵か」「単なるフェンスか」の
区別はできない（`function=2000`が付くだけ）。これは検証結果として重要な制約。

### 想定される抽出方法（未検証、データ未入手のため）

CityGML内の`frn:CityFurniture`要素のうち`frn:function`が`2000`のものを
フィルタし、そのジオメトリ（LOD1なら直方体、LOD2/3ならより詳細な形状）から
3Dバウンディングボックスを求める、という方針を想定していた（下記ブロッカーにより未実装）。

## 4. データ入手（ブロック・未達成）

PLATEAUのCityGML配布元は公式には以下の2つのみ：

- `https://www.mlit.go.jp/plateau/open-data/`
- `https://www.geospatial.jp/ckan/dataset/...`（G空間情報センター）

このサンドボックス環境では、**両ドメインともネットワークegressポリシーで
接続そのものがブロックされている**（サイズの大小に関係なく到達不可）。
GitHub上のミラーやAWS S3バケットでの代替配布も探したが見つからなかった。
参考までに実データは1都市分で目安1.4GB程度で、いずれにせよ「軽い確認」で
済む規模ではない。

この時点でユーザーに確認し、**「ここで実験を保留する」**という判断を得た。
そのため、ステップ2（データ取得・パース）〜ステップ4（教師データ変換の検証）は
未着手。

## 5. 再開する場合に必要なもの

- 実際にダウンロードした小さめのPLATEAU CityGMLサンプル一式
  （`udx/frn/*.gml` を含むもの）をこのフォルダにアップロードしてもらう
  （サイズは事前に確認・合意した上で）
- または、ブロックされていないホストから同等データを入手できる経路が見つかること

再開後にやること（未着手）：

1. `experiments/plateau-fence/sample/` にサンプルCityGMLを配置
2. `experiments/plateau-fence/src/` にCityGMLパーサ（`lxml`等）を実装し、
   `frn:function=2000`の`CityFurniture`要素を抽出。出力は以下のJSON形式：
   ```json
   {
     "id": "...",
     "category": "fence",
     "original_category": "柵・壁 (function=2000)",
     "source": "PLATEAU CityGML",
     "geometry_type": "...",
     "bbox_3d": {
       "min": {"x": 0, "y": 0, "z": 0},
       "max": {"x": 0, "y": 0, "z": 0}
     }
   }
   ```
3. `experiments/plateau-fence/output/preview/` に、抽出したフェンスを
   ハイライトした簡易可視化を出力（人間が目視確認できる形）
4. 仮想カメラでRGB画像＋バイナリマスク（`image_000N.png` /
   `mask_000N.png`、0=背景・1=フェンス）のペア生成が可能か調査・試作

## 6. 結論（現時点）

「PLATEAUデータでフェンスを検出用教師データにできるか」という問いに対して、
**仕様レベルでは「フェンス・柵・ガードレールは`frn:function=2000`として
まとめて取得できる見込みがある」ことまでは確認できたが、実データでの検証は
サンドボックスのネットワーク制約により未達成**。実データへのアクセス経路が
確保でき次第、この続きから再開できる状態で保留している。
