# Decisions

設計判断の正本。

## 決めたこと

### 2026-09-20 / D001
**完全自動作曲ではなく、ルールベースの翻訳を核にする。**

理由:
- 場所と音の関係を説明できる
- 人間の着眼点を資産化できる
- AIモデルを交換しても思想が残る

### 2026-09-20 / D002
**v0.1は動画解析そのものではなく、検出結果→音楽構成に集中する。**

理由:
- 問題を分割できる
- 早く動くものを作れる
- 物体認識方式に依存しない

### 2026-09-20 / D003
**街だけに限定しない。**

City / Food / Festival / Landscapeへ展開できる構造にする。

### 2026-09-20 / D004
**作品の成功条件は「BGMとして流れて違和感がないこと」を優先する。**

理由:
- 毎回、強い主張を持つ曲にする必要はない
- 「曲としてすごくかっこいい」ことは必須条件にしない
- 映像と一緒に自然に流せることを優先する

### 2026-09-20 / D005
**直訳できる音はなるべく直訳する。1つの対象には複数の音候補を持てるようにする。**

例:
- car → engine / brake / tire friction
- bicycle → bell / chain
- construction → metal hit / drill / machine hum

方針:
- まず少数の候補から始める
- 種類は後から追加できる構造にする
- 状況に応じた選択やランダム選択も将来可能にする

### 2026-09-20 / D006
**制作方針は「8割自動 + 人間が仕上げる」とする。**

理由:
- 完全自動をゴールにしない
- 人間の着眼点と最終判断を残す
- 自動化は提案、初期配置、素材整理を主に担う

### 2026-09-20 / D007
**最初の音源はサンプルベースで進める。**

理由:
- 立ち上がりが早い
- まずは変換ルールと作品構造を検証できる
- 現地録音やシンセ設計は後から追加する

### 2026-09-20 / D008
**認識枠は見せる。ただし音が出る瞬間だけ表示する。**

理由:
- 常時表示より映像ノイズが少ない
- どの対象がどの音を発火させたか分かる
- 映像上のイベントと音の同期を強められる

### 2026-09-20 / D009
**オープニングで主要な音を短く一気に提示し、「TOAST STUDIO」の文字を出す演出を採用候補とする。**

方針:
- 冒頭で、その作品内の主要な音を「バーッ」と短く提示する
- 同時に「TOAST STUDIO」を表示する
- 文字そのものにも音を割り当てる
- 将来的には、その作品で使う素材音だけでロゴサウンドを作る案も検討する

### 2026-09-20 / D010
**第一作は池袋を題材にし、最初は写真、その後に動画へ進む。**

理由:
- 生活圏で撮影しやすい
- 継続的に試しやすい
- 静止画で変換ルールを確認してから、時間変化のある動画へ発展できる

## OPEN DECISIONS

### O001 — 池袋第一作の具体的な画角
候補:
- 西口の道路・交差点
- 駅前の人流
- 車道 + 看板 + 空
- 工事現場のある通り
- 昼 / 夜

### O002 — 写真1枚を時間軸へ変換するルール
候補:
- 左から右へスキャン
- 強い対象から順に鳴らす
- 中央に近い対象から鳴らす
- 役割ごとに段階的にレイヤーを足す

### O003 — TOAST STUDIO ロゴサウンド
- 文字ごとに音を割り当てる
- 短いジングルを鳴らす
- その作品で使う素材音だけで構成する
